> handed to nano-pro-web as a copy — it belongs in that repo's `.locally_ignored/`, next to
> the 1.10.0 handover. **Every unprefixed path and link below is nano-pro-web's and resolves

The library side is done and packed. `@palimp/*` **1.12.0** answers the owner's three asks of
2026-10-20 — *keep preview/edit mode when changing the route*, *say that unsaved changes have to
be saved before they can be published*, and *improve the flow* — in two releases, **1.11.0 and
1.12.0, vendored here as one step**. 1.11.0 was never packed on its own; there is no reason to
land it separately. Both are pushed, as stacked PRs on the fork:
[#15](https://github.com/mishishishi/palimp/pull/15) (`pr/12-editor-flow-mode-publish-guard`,
1.11.0, into #14) and [#16](https://github.com/mishishishi/palimp/pull/16)
(`pr/13-editor-flow-drafts`, 1.12.0, into #15).

**There is no host code change in this release.** The `extraTargets` prop the layout already
passes picks up the new behaviour by itself.

## What 1.11.0 + 1.12.0 actually change

Three new runtime files, ten changed ones and five version bumps. Everything new is in the
admin half, behind the same `next/dynamic` boundary as before, except two small changes to
modules this host already loads eagerly (step 5).

| file | change |
| --- | --- |
| `libs/fe-next/src/PalimpProvider.tsx` | **eager.** `preview` persisted in `sessionStorage` under `palimp:preview`, read in the effect that reads the session — only when `hasSession()` is true, so a visitor's storage is never read or written. `reset()` clears it |
| `libs/core/src/PalimpDrawerAction.ts` | **new optional field** `publishesSavedContent?: boolean` — type only |
| `libs/publish-github/src/react.tsx` | **eager.** Every `extraTargets` entry now sets `publishesSavedContent: true` |
| `libs/core/src/Admin/Devtools/useUnsavedChangesGuard.tsx` | **new**, admin-only: the *N unsaved changes won't be published* modal, shared by Publish and every flagged action |
| `libs/core/src/Admin/draftsPersistence.ts` | **new**, admin-only: mirrors the edit buffer to `localStorage` under `palimp:drafts`, hydrates it on load, follows other tabs |
| `libs/core/src/Admin/Devtools/ChangesModal.tsx` | **new**, admin-only: the list of unsaved changes, with per-row and all-at-once Discard |
| `libs/core/src/Admin/Devtools/index.tsx` | click-outside rewritten (confirms no longer close the drawer); drafts persistence started; the restore notice; the float button's eye icon in preview |
| `libs/core/src/Admin/Devtools/DevtoolsContent.tsx` | drawer sized by content (no more fixed `40vh`); Changes icon beside Save; logout popconfirm with drafts pending; name and email ellipsise |
| `libs/core/src/Admin/Devtools/useSaveButton.tsx` | `Save failed` with the error; `requestSave()` resolves whether the save happened |
| `DrawerActionButton.tsx`, `useDrawerAction.ts`, `DevtoolsContext.tsx`, `editsStore.ts` | the guard threaded through; logout discards drafts; `editsStore.replaceAll` |

**No adapter contract, store schema, `exports` map or peer range moved.** `@palimp/core`'s root
entry is byte-identical in size to 1.10.0's; no new eager module exists.

### What the editor sees

**1.11.0**

1. **Preview mode survives a reload and a locale switch.** It is kept per tab: a new tab, and
   any sign-out and sign-in, start in edit mode. Step 0 of the plan, run on this host's preview
   on 2026-10-20, found the header links are soft navigations — the mode already survived those.
   What lost it were document loads: a reload, `LocaleSwitcher` (a document load by design), and
   any plain `<a>`.
2. **The floating button says which mode you are in** — a pencil in edit mode, an eye with a
   `Preview mode` tooltip in preview — so a page reloaded into preview, with no textareas on it,
   explains itself while the drawer is closed.
3. **Publish with unsaved changes asks first.** With `Save (N)` pending, Publish — and
   `Publish live site`, through the flag — opens *N unsaved changes won't be published* with
   **Cancel**, **Publish without them** and **Save and publish** (primary, **focused**). Save and
   publish runs the ordinary Save, including the Projects collection confirm, and publishes only
   if that save succeeded. With nothing pending, Publish runs at once, as before. While drafts are
   pending, hovering either button shows *N unsaved changes won't be included*.
4. **For `Publish live site`, this question comes before the live-site confirm.** The editor
   answers the drafts question, then sees this host's *Publish the live site?* with **Cancel**
   focused, as before.
5. **A failed Save says so**: `Save failed`, the error under it, the button enabled as the retry,
   the drafts kept. Until now it went back to `Save (N)` as if nothing had happened.
6. **Answering a confirm no longer closes the drawer.** Publish live site's, Save's, Discard's,
   logout's — the editor now sees `Running...` and the result line without reopening the drawer.
7. **The drawer fits its content.** The fixed `40vh` body is gone; it sizes to its buttons and
   only scrolls on a viewport shorter than its content (past `100vh - 32px`). The horizontal
   scrollbar a long e-mail address caused (in every 1.10.0 screenshot) is gone too.

**1.12.0**

8. **Unsaved changes survive a reload, a locale switch and a closed tab.** They are kept per
   browser and shared by its open tabs: a Save or a Discard in one tab clears the others.
9. **After a reload that brought drafts back**, a bottom-left notice, once per tab: *Restored N
   unsaved changes*, with **Review** (opens the Changes list) and **Discard** (behind a confirm).
10. **The Changes list** — an icon button beside Save, disabled at `Save (0)` — lists every
    pending draft from every page: its field label where this page registered one, else the raw
    key; the new text, with an **emptied field shown as `(empty)`**; the stored value struck
    through under it when it is known; a **Discard** per row and **Discard all**. Discarding is
    local and never touches saved content.
11. **The drawer's sign-out asks when drafts are pending** — *Discard N unsaved changes?* — and
    discards them. Signing out with nothing pending is immediate, as before.

### Behaviours to know before someone reports them as bugs

- ⚠ **A reload is no longer a way to throw edits away.** This host's docs teach it as one (step
  8). The way back is now the Changes list's Discard, or the restore notice's.
- ⚠ **A restored draft overwrites whatever was saved since it was typed.** A draft is a value, not
  a diff. One typed last week and restored today replaces the stored text on the next Save, even
  if somebody else changed it in between. The struck-through stored value in the Changes list is
  how the editor sees that; nothing compares them automatically.
- ⚠ **Drafts belong to the browser, not the account.** They are not on the server until Save. A
  draft typed on one computer does not exist on another; a draft left in a shared browser is
  restored to whoever signs in there next. Only the drawer's own sign-out discards them —
  **deliberately not** the *Sign out* of the session-expired screen, which is how an editor whose
  session lapsed gets back in to save exactly that work.
- ⚠ **The preview and the live site keep separate drafts.** They are different origins, so
  separate `localStorage`. A draft typed on the preview is not in the live site's editor, and the
  guard on the preview's `Publish live site` counts the preview's drafts only — which is right,
  since those are what that editor can see.
- ⚠ **A locale switch keeps the other locale's drafts in the count.** Keys are
  `${locale}.${key}` here (`src/lib/palimp.ts`), and the buffer is one per document, now one per
  browser. After typing on `/cs/…` and switching to `/en/…`, `Save (N)` still counts the Czech
  draft, Save writes it, and the Changes list shows it — **probably as its raw `cs.…` key**, since
  labels come only from what the current page registered. Not checked on this host.
- ⚠ **Enter on the drafts modal is Save and publish.** The owner's choice (D4): the usual intent
  is to include the edits. For `Publish live site` that is still not a live publish — the
  live-site confirm comes next, with Cancel focused.
- **An emptied field still does not glow** (editing-copy §1) — unchanged. It is now visible in
  the Changes list as `(empty)`.
- **Unchanged from 1.10.0:** a dead token disables Publish but not `Publish live site`, which
  fails after the press with the auth cause; `statusText` is empty over HTTP/2.
- **Visitors are untouched.** Both new storage keys are read and written only for a signed-in
  editor: `palimp:preview` behind `hasSession()`, `palimp:drafts` from the lazy admin half. The
  privacy page's *no cookies, only the consent record in localStorage* stays true for visitors.

```sh

pnpm build:pages
pnpm weight
```

There is no prop to add, so there is one measurement, not two — but it still needs a
**same-HEAD 1.10.0 baseline built first**; row L is not a valid before. **Expect a small eager
move**, in two modules already in the eager graph (the `[locale]` layout imports both
statically), so growth and not a new edge:

| module | 1.10.0 | 1.12.0 | |
| --- | --- | --- | --- |
| `fe-next/dist/PalimpProvider.js` | 491 B | 958 B | the `sessionStorage` read/write |
| `publish-github/dist/react.js` | 781 B | 873 B | one property, and its comment |
| `core/dist/index.js` (root) | 296 B | 296 B | unchanged |

Those are gzipped `dist` files, comments included; after this host's minifier, expect a few
hundred bytes per page, under 0.5 KB. HTML and RSC should not move — no new strings reach a
page. If `check-eager-chunks` reports `@palimp/core/admin` (antd, react-query, lucide) in an
eager chunk, **stop and report it**: the new admin modules are all under `Admin/`, and the root
entry imports nothing from there.

### 6. The host change — none

`extraTargets` in `src/app/[locale]/layout.tsx` stays exactly as it is: `publish-github` sets
`publishesSavedContent` on every target it maps, so `Publish live site` is guarded without a
change here. The guard's strings are palimp's (English), as Publish's always were.

### 7. Verify for real

**No build in either repo can see any of this.** On the palimp side every check in the plan
passed on 2026-10-20 against `examples/supabase-next`, served as a static export, with the
drawer driven over CDP — the record is [`plans/editor-flow.md`](../plans/editor-flow.md)
§Verification, twice. **Every GitHub dispatch there was intercepted in the browser**, so the
code paths end at "the request was made"; nothing was deployed, Firebase was not run, and
`LocaleSwitcher` does not exist there. So, on the preview deploy:

1. **Mode across a locale switch.** Preview mode on → `LocaleSwitcher` → still preview, and **no
   textarea flashes** before the text renders. Reload → still preview. New tab → edit mode.
   Sign out and in → edit mode. The float button shows the eye in preview.
2. **Drafts across a locale switch.** Type on `/en/…`, switch to `/cs/…`: `Save (1)` and the
   restore notice. Open the Changes list: record how the English draft is labelled (the
   ⚠ above). Discard it there; the count goes to 0.
3. **A second tab follows.** Type, open a second tab: same count. Discard all in one → the other
   reads `Save (0)`.
4. **Publish with a draft.** The modal, Save and publish focused. **Cancel** → nothing
   dispatched, the drawer still open. **Save and publish** → `Saving...`, then the preview's run
   dispatched, `Save (0)`, drawer open throughout. Use an edit that writes back the text already
   there, or one meant to ship.
5. **`Publish live site` with a draft.** The drafts modal first, then this host's live-site
   confirm, Cancel focused. ⚠ **Cancel there.** OK rebuilds the live site — do it only when the
   saved content is meant to go live, or ask first.
6. **The drawer at 1280×776 with `Publish live site` present does not scroll.** ADR 075
   measured 30 px of overflow idle and 132 px with an error at 1.10.0; both should be gone.
7. **Sign-out with a draft** → *Discard 1 unsaved change?* → sign out → `palimp:drafts` gone from
   `localStorage` (DevTools → Application); sign back in → `Save (0)`, no notice.
8. **A visitor's storage is untouched.** Signed out, in a fresh profile: no `palimp:*` key in
   `localStorage` or `sessionStorage` after visiting a few pages and switching locale.
9. **The live build is unaffected** beyond the version: no `Publish live site`, and a draft typed
   on the preview is not in the live editor's count.

### 8. Commit, and the docs that become false

The four tarballs, `vendor/palimp-manifest.json`, `package.json`, `pnpm-lock.yaml` — one commit,
`chore(palimp): vendor 1.12.0 tarballs`. No layout commit this time. Then the docs, which this
release contradicts in more places than 1.10.0 did:

- **`agent-guidelines/editing-copy.md` §1** — *"nothing is persisted"*, *"reloading the page,
  which discards every pending edit at once"*, *"a closed tab or a Back press takes unsaved work
  silently"* are all false now. Drafts persist in the browser until Save, a Discard in the Changes
  list or the notice, or the drawer's sign-out. *"There is no equivalent for in-place text"* (of
  the Collections Discard) is false too: the Changes list has a Discard per row. The note on the
  emptied field gains *it shows as `(empty)` in the Changes list*.
- **`editing-copy.md` §3** — *"Answering it closes the drawer"* is false; and the drafts modal
  belongs in the Save → Publish → `Publish live site` flow it describes.
- **`editing-copy.md` §6** — preview mode now outlives a reload and a locale switch, per tab; the
  float button shows an eye; sign-out asks when drafts are pending.
- **`editing-copy.md` §8** — *"Nothing can list what is pending"* stays **true** of what it means
  (Saved but not yet published). The Changes list shows *unsaved* drafts only. Worth one
  sentence keeping the two apart, because "Changes" invites the confusion.
- **`docs/running.md` §Publish, from the live editor** — *"Answering the confirm closes the
  drawer"* is false. Its first sentence, *"The editor's Publish button saves the change, then asks

- **`agent-guidelines/decisions/075-the-live-site-is-published-from-the-preview-drawer.md`** §Consequences, *Known quirks* — the first two (confirm
  closes the drawer, fixed `40vh` scrolls) are fixed in 1.11.0; the dead-token one stands.
- **`agent-guidelines/architecture.md`** §Stack: `1.10.0` → `1.12.0`.
- **`agent-guidelines/revendoring-palimp.md`** status line → 1.12.0, today's date.
- **`agent-guidelines/decisions/039-palimp-adoption.md` §The number: add a row**, against the
  same-HEAD 1.10.0 baseline from step 5.
- **The client PDF guides** are derived
  ([ADR 071](agent-guidelines/decisions/071-client-guides-are-a-derived-artifact.md)) —
